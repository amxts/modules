# Как добавить модуль

[English](CONTRIBUTING.md) | **Русский**

Модуль попадает в каталог amxts — [модули](https://amxts.github.io/ru/modules)
на сайте и список команды `amxts` — через pull request, который добавляет
сюда его запись. Одной публикации на npm мало: в каталоге только то, что
перечислено в этом репозитории.

## Перед тем как открыть его

Модуль — это пакет-модуль amxts (см.
[создание модуля](https://amxts.github.io/ru/docs/modules/creating-a-module)),
и ещё:

- его репозиторий на GitHub публичный, с `README.md` — это страница модуля на
  сайте — и `LICENSE`;
- в `package.json` в корне репозитория — `name` пакета, поле `amxts` с
  `module` и `@amxts/core` в `peerDependencies` диапазоном версий, в который
  входит текущее ядро (`^0.1.0`);
- в `package.json` нет скриптов `preinstall`, `install` и `postinstall`;
- он опубликован на npm, и опубликованный `package.json` указывает в
  `repository` тот же репозиторий на GitHub.

## Pull request

1. Сделайте форк этого репозитория.
2. Добавьте `modules/<name>.yml`: поля описаны в [README](README.ru.md#запись).
   `type` — `community`, `category` — та, что подходит лучше всего.
3. Проверьте его, если у вас есть [Bun](https://bun.sh):

   ```sh
   bun install
   bun run validate <name>
   ```

4. Откройте pull request. CI его проверит, мейнтейнер просмотрит, и после
   слияния модуль в каталоге: `modules.json` пересобирается в `main`, сайт
   подхватывает его со следующей сборкой (раз в день), а `amxts` — через
   несколько минут.

`modules.json` руками не правится: его собирает CI из записей.

## Что проверяет CI

Каждую запись, на каждый pull request и пуш:

- **файл**: YAML только с известными полями; `name`, `npm`, `repo`,
  `description`, `category`, `type` и `maintainers` на месте; `name` строчными
  через дефис и совпадает с именем файла; `category` и `type` — из своих
  списков; `logo` — путь внутри репозитория;
- **другие записи**: ни пакет npm, ни репозиторий не перечислены дважды, и
  нет имени, похожего на чужое, — `menu-c0re` рядом с `menu-core` это ошибка,
  а имя, отличающееся от другого одной буквой, — предупреждение для ревьюера;
- **репозиторий**: он публичный, в нём есть README, LICENSE и логотип, если
  он указан; его `package.json` называет пакет из `npm`, содержит
  `amxts.module`, принимает текущее ядро `@amxts/core` в диапазоне peer и не
  имеет скриптов установки;
- **npm**: пакет опубликован, и его `repository` — тот, что в записи.

Ошибка валит проверку; предупреждение остаётся на усмотрение ревьюера.

## Официальные и от сообщества

Официальный модуль делает команда amxts: `@amxts/<name>` на npm и
`amxts/<name>` на GitHub, `type: official`. Этот scope и эту организацию
может занимать только официальный модуль, и официальный модуль занимает оба.
Любой другой модуль — `type: community`, под именем своего автора.

Официальный модуль проходит те же проверки, что и модуль от сообщества: он
есть в npm и просит ядро диапазоном версий. (`OFFICIAL_ON_NPM` в
`src/checks.ts`, выставленный в `false`, делает «ещё нет в npm» и локальную
ссылку на ядро в `peerDependencies` предупреждениями для официальных
модулей — чтобы внести модуль в каталог до публикации.)

Что модуль просит от ядра, читается из его пакета на npm, когда он
опубликован, иначе — из репозитория: репозиторий может ссылаться в
`peerDependencies` на папку ядра, как checkout рядом с ядром, и публиковать её
диапазоном версий.

## Как изменить или убрать запись

Pull request, который правит или удаляет файл, от одного из её
`maintainers`. Модуль, чей репозиторий пропал, архивирован или перестал
проходить проверки, команда amxts может убрать.
